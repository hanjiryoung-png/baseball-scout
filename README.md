# 찐팬의 데이터 덕아웃 — 나만의 KBO 스카우팅 리포트

이 버전은 Render 배포용입니다. 사용자는 배포 후 생성되는 웹주소만 클릭하면 됩니다.

## 핵심 기능
- 일반 홈페이지/앱 형태의 화면: 홈 / 경기 추가 / 팀 / 선수
- 경기 입력칸은 '경기 1, 경기 2...'로 표시
- 한 번 저장한 gameId는 NAVER에 다시 요청하지 않음
- 경기 데이터를 SQLite에 계속 누적
- Render Persistent Disk(`/var/data`)에 DB 영구 저장
- 새 경기 저장 성공 시 `presentation_snapshot.db` 자동 생성/갱신
- `발표 모드` ON:
  - 경기 추가 메뉴 숨김
  - NAVER에 신규 요청을 보내지 않음
  - 저장된 경기만으로 팀/선수 분석 및 그래프 시연
- 403/429 발생 시 자동 재시도/우회 없이 즉시 중단
- 시즌 전체 자동수집 기능 없음

## 발표 전에 권장
1. KT·LG·삼성·두산·KIA 관련 경기를 여러 경기 미리 추가합니다.
2. 팀 분석과 선수 분석이 정상 출력되는지 확인합니다.
3. 발표 직전 `발표 모드`를 켜고 저장 데이터만으로 모든 화면이 열리는지 확인합니다.
4. 신규 경기 자동수집 기능은 네트워크가 정상일 때만 추가 시연합니다.

## Render 배포
이 저장소 루트에 `render.yaml`이 있습니다.
Render에서 GitHub 저장소를 연결해 Blueprint로 생성하면:
- Starter Web Service
- Singapore region
- 1GB Persistent Disk `/var/data`
구성이 적용되도록 작성했습니다.

`app.py`, `requirements.txt`, `render.yaml`을 GitHub 저장소 루트에 올리면 됩니다.

## 주의
NAVER Sports의 내부 데이터 구조는 외부 개발자를 위한 공식 API 사양으로 보장된 것이 아니므로 향후 변경될 수 있습니다.
본 프로그램은 연구용 프로토타입이며, 제한된 범위의 경기 데이터를 사용하도록 설계했습니다.
